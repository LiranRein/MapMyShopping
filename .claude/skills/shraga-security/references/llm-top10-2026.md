# OWASP Top 10 for LLM Applications 2026 - Vibe-Coding Mapping

Baseline version: OWASP Top 10 for LLM Applications 2026 (genai.owasp.org), published August 2026. Last verified: 2026-10-14.
Changes vs 2025: Excessive Agency moved up to #3; System Prompt Leakage replaced by Hidden Context Exposure (#8), which also covers retrieved documents, memory, user data, app state and tool responses.
Run the Freshness Protocol before relying on this file for a PRD.

Apply to any product that calls an LLM: chat, generation, summarization, RAG, classification, AI features inside a regular app.

---

## LLM01 - Prompt Injection
**Risk:** user input or content the model reads (documents, web pages, emails, tool results) overrides the app's instructions.
**Check:** where untrusted text enters a prompt; what the model can do with its output.
**Control:** separate instructions from data (clear delimiters, structured messages); never let model output directly trigger privileged actions; human confirmation for sensitive actions; limit tools and permissions (see LLM03).

## LLM02 - Sensitive Information Disclosure
**Risk:** the model reveals PII, secrets or other users' data, from its context or from connected data.
**Check:** what data is sent to the model; whether context mixes data from different users or tenants.
**Control:** send the minimum data needed; per-user context isolation; redact PII where possible; review the provider's data retention and training terms.

## LLM03 - Excessive Agency
**Risk:** the model has more tools, permissions or autonomy than its task needs, so a manipulated model causes real damage.
**Check:** list every tool / action the model can trigger and with what permissions.
**Control:** least agency - minimal tools, read-only by default, scoped credentials, confirmation for write / delete / send / pay actions. For agentic products also apply `agentic-top10.md`.

## LLM04 - Supply Chain
**Risk:** compromised or unvetted models, SDKs, plugins, MCP servers, prompt templates or datasets.
**Check:** source and maintenance status of every AI component.
**Control:** official SDKs and providers; pin model versions; vet third-party MCP servers and plugins before use.

## LLM05 - Data and Model Poisoning
**Risk:** manipulated training, fine-tuning or RAG data changes model behavior.
**Check:** who can write to the knowledge base / vector store; whether user content is indexed.
**Control:** restrict and log writes to knowledge sources; validate ingested documents; separate user-submitted content from trusted knowledge.

## LLM06 - Unbounded Consumption
**Risk:** uncontrolled AI usage drives cost explosions or denial of service ("denial of wallet").
**Check:** limits per user, per request and per day; max tokens; context size.
**Control:** rate limits and quotas per user; max output tokens; context trimming; usage and cost logging; billing alerts at the provider. Critical if combined with an exposed API key.

## LLM07 - Misinformation
**Risk:** confident but wrong output that users rely on (hallucination).
**Check:** where output is presented as fact or drives decisions.
**Control:** grounding / RAG with citations; clear UI labeling of AI content; human review for high-stakes output; evaluation set for key prompts.

## LLM08 - Hidden Context Exposure
**Risk:** content the user should not see leaks through the model: system prompt, retrieved documents, agent memory, other users' data, app state, tool responses.
**Check:** what is placed in context that the current user is not authorized to see.
**Control:** never put secrets or authorization logic in prompts; filter retrieved content by the user's permissions before it enters context; assume anything in context can be revealed.

## LLM09 - Vector and Embedding Weaknesses
**Risk:** RAG stores leak data across users or tenants, or are manipulated to surface malicious content.
**Check:** access control on the vector store; tenant filtering on retrieval.
**Control:** permission-aware retrieval (filter by user / tenant at query time); access control on the vector DB; validated ingestion.

## LLM10 - Improper Output Handling
**Risk:** model output is used without validation, causing XSS, SQL injection, broken JSON or unsafe actions downstream.
**Check:** every place where model output is rendered, stored, executed or passed to another system.
**Control:** treat output as untrusted user input; schema validation for structured output with retry and fallback; encode before rendering; never execute model output directly.

## Quick checklist (AI phases)

- [ ] LLM01 Instructions separated from untrusted content; no direct privileged actions from output
- [ ] LLM02 Minimum data sent; per-user context isolation; provider data terms reviewed
- [ ] LLM03 Tools and permissions minimal; confirmation for write / send / pay
- [ ] LLM04 Official SDKs; pinned model versions; vetted MCP / plugins
- [ ] LLM05 Writes to knowledge sources restricted and logged
- [ ] LLM06 Per-user rate limits, max tokens, cost logging, billing alerts
- [ ] LLM07 AI content labeled; citations or human review where stakes are high
- [ ] LLM08 No secrets in prompts; context filtered by user permissions
- [ ] LLM09 Permission-aware retrieval in RAG
- [ ] LLM10 Output validated and encoded before use
